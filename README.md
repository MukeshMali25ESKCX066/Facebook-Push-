# PageCrew

PageCrew is organized as a frontend/backend project:

- `frontend/public/` contains the production frontend build and static pages.
- `backend/` contains the compiled Node.js API and its package manifest.
- `serve-pagecrew.py` serves the frontend on port 5173 and proxies `/api/*` to the backend on port 4000.
- `backend/dist/services/ai-content.js` and `frontend/public/ai-content.*` implement the campaign AI content workflow.
- `backend/dist/services/scheduler-core.js`, `backend/dist/routes/scheduler.js`, and `frontend/public/scheduler.*` implement event-based, per-Page scheduling, calendar review, and publishing controls.
- `backend/dist/services/analytics-core.js`, `backend/dist/services/analytics-integrations.js`, `backend/dist/routes/analytics.js`, and `frontend/public/analytics.*` implement PageCrew publishing analytics, optional GA4 traffic sync, reports, and reviewed optimization suggestions.
- `frontend/public/advanced-hybrid.*`, `backend/dist/routes/automatic-campaigns.js`, `backend/dist/routes/media-library.js`, and `backend/dist/routes/scheduler.js` provide the Automatic Auto Publishing flow: campaign setup, resource matching, AI generation, readiness review, explicit activation, queue processing, publishing history, analytics, and lifecycle controls.

## Run locally

1. Copy `backend/.env.example` to `backend/.env` and set private credentials. Use Node.js 22 or newer and set `GEMINI_API_KEY` in the backend environment for AI content and image generation (`AI_PROVIDER=gemini`, `GEMINI_MODEL=gemini-3.6-flash`, `GEMINI_IMAGE_MODEL=gemini-nano-banana-2.1`). Captions, CTAs, hashtags, and image variations use the official Google GenAI SDK server-side; `OPENAI_API_KEY` is not required for the AI Content Generator.
2. In `backend/`, install dependencies with `npm install` if needed, then run `npm start`.
3. In a separate terminal at the project root, run `python serve-pagecrew.py`.
4. Open <http://127.0.0.1:5173>.

Open <http://127.0.0.1:5173/advanced-hybrid> for Automatic Auto Publishing. The workflow supports campaign drafts, Facebook Page permission checks, pasted URLs, CSV/XLSX imports, and same-site homepage/sitemap discovery (up to 200 URLs per scan), with URL search after discovery. Step 5 provides single, multiple, folder, and ZIP image uploads, previews, folder-wise browsing and selection, categories, tags, replacement/deletion, campaign selection, and usage history. The image library accepts JPG/JPEG, PNG, and WEBP, with a 500-image/1 GB workspace limit, 8 MB per image, and 200 images/100 MB expanded per ZIP. Step 6 builds a plan that uses every selected URL and image, keeps each Page's resources unique within a round, and avoids prior Page/URL/image combinations when possible. Step 7 saves AI caption preferences and generates one or all missing rounds only when requested. Step 8 saves weekly posting times, per-Page intervals and limits, timezones, approval, weekend, and retry settings; saving the configuration does not start publishing. Step 9 refreshes the selected Facebook Page permissions and checks URLs, stored images, AI configuration, approvals, dates, and future schedule capacity before explicit activation. Steps 10–12 display automatic processing, Facebook results, and publishing history; Step 13 shows Meta Insights and optional GA4 sessions; Step 14 provides pause/resume/stop and setup links. A stopped campaign can be edited and activated with a replacement schedule; active or paused campaigns must be stopped before changing resources or settings.

Campaigns, generated content, settings, provider usage, and generation errors are stored in encrypted persistence. Configure optional `GEMINI_*_USD_*` and `OPENAI_*_USD_*` rate values using current provider pricing to record estimated USD costs; estimates are omitted when rates are unset.

Run backend unit tests with `npm test` from `backend/`.

The event-based scheduler supports two modes. Automatic mode queues generated posts (including drafts) into future Page-specific slots without schedule review; manual mode requires approved content and a reviewed schedule before starting. Both use timezone-aware scheduling, independent Page limits and minimum gaps, Facebook UTM parameters, calendar views, and post editing/rescheduling. Automatic Auto Publishing uses its separate explicit Step 9 activation: all matching rounds must have generated captions, and posts must be approved unless automatic approval is enabled. Its queue is persisted in the encrypted `scheduler.enc` store, publishes selected media-library images through Meta, honors configured weekly times, per-Page limits/intervals and retry attempts/delay, and is processed by the running Node.js backend every 30 seconds. Publishing results are recorded; an ambiguous in-flight publish after a restart is held for review to avoid accidental duplicates. Pause, resume, and stop are available from the Automatic Auto Publishing operations views.

The backend encrypts event campaigns, automatic campaigns, the media-library catalog, and scheduler data under `PAGECREW_DATA_DIR` (default: `$HOME/pagecrew-data`) using `ENCRYPTION_KEY`. Generated AI images and uploaded media-library files are stored under that same directory. Existing generated images in `backend/uploads/ai-generated` are copied there on backend startup when missing. Set both variables in the backend environment. On Render, the default filesystem is ephemeral: create a persistent disk mounted at `/var/data` and set `PAGECREW_DATA_DIR=/var/data/pagecrew-data` to retain campaigns, schedules, generated images, and uploaded images across restarts or deploys. Keep the same `ENCRYPTION_KEY` across deployments; changing it prevents previously saved data from being decrypted. The scheduler uses the persistent Node.js worker model; keep the backend process running and reconnect/load Facebook Pages before campaign posts are due. Scheduler endpoints are mounted under `/api/scheduler`; Automatic Auto Publishing campaign endpoints are mounted under `/api/automatic-campaigns`. Homepage article discovery is authenticated, same-origin only, and bounded; article preview/discovery reject local and private network targets.

The Analytics page is available at `/analytics.html`; its workspace-scoped endpoints are mounted under `/api/analytics`. Published post insights are fetched from Meta on demand and remain N/A until sync succeeds; unsupported metrics or missing permissions are not fabricated. Reconnect/load Facebook Pages before syncing so Page access tokens are available. GA4 is optional: set `GA4_PROPERTY_ID` and `GA4_SERVICE_ACCOUNT_JSON` in the private backend environment, share the GA4 property with that service account as a Viewer, and use the GA4 Data API. UTM-attributed GA4 sessions are displayed separately from Facebook link clicks. Analytics AI optimization recommendations continue to use the optional OpenAI API and require `OPENAI_API_KEY`; suggestions do not modify or publish content, and users must approve or reject them. Reports support CSV, Excel-compatible CSV, and a printable page for saving as PDF. Best-time comparisons are observational and show low confidence when there is limited history.

Configure local secrets and service settings in `backend/.env`. Do not commit that file.

Configure Vercel with the repository as its Root Directory and `frontend/public` as its Output Directory so the repository-root `vercel.json` serves the static frontend and proxies `/api/*` to `https://facebook-push.onrender.com`. If the Vercel Root Directory is set to `frontend` instead, use `public` as the Output Directory; `frontend/vercel.json` provides the equivalent API and page rewrites. The Render backend must also be running for API requests. The default Facebook OAuth scope requests `pages_show_list`, `pages_manage_posts`, and `pages_read_engagement`; users with an existing connection must reconnect to grant newly requested permissions. If `META_SCOPE` is set, include the required Page permissions there as well. Set `GEMINI_API_KEY` (and optionally `AI_PROVIDER=gemini`, `GEMINI_MODEL=gemini-3.6-flash`, and `GEMINI_IMAGE_MODEL=gemini-nano-banana-2.1`) in the Render backend's environment variables, then restart/redeploy that backend. Set the backend `FRONTEND_URL` to `https://pagecrew.vercel.app` when using this production frontend. A Vercel-only environment variable is not forwarded by this proxy to Render. Keep the Gemini key server-side; it is never sent to the browser.

To test the backend's Gemini connectivity while signed in, send `POST /api/campaigns/ai/health`. It performs a small request with the configured model and reports whether the backend loaded the key, the model used, and sanitized provider status details; it never returns the key.

This checkout contains the built frontend and compiled backend output; the original frontend and backend source files are not included.
